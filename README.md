## 🧠 Концепция и методология управления скотом

Система работает по принципу **оперантного обусловливания (условный рефлекс Павлова)**, аналогично мировым коммерческим решениям *Nofence* (Норвегия), *Halter* (Новая Зеландия) и *Gallagher eShepherd* (Австралия).

Вместо физических заборов натягиваются **виртуальные границы (Geofences)** в веб-интерфейсе спутниковой карты. Ошейник непрерывно определяет координаты животного и автоматически корректирует его траекторию движения.

### Главный закон пастьбы: «Мгновенная награда»
* Скот **не наказывается постфактум**. Наказание без понятной альтернативы вызывает панику.
* При приближении к границе ошейник заблаговременно предупреждает животное звуком.
* Если животное разворачивается и делает пару шагов назад вглубь пастбища — **звук и раздражители мгновенно отключаются**.
* В течение 3–4 дней у скота формируется устойчивая причинно-следственная связь: **«Пошел на звук $\rightarrow$ неприятно, повернул обратно $\rightarrow$ покой и тишина»**.

## ⚡ Градация воздействия

Воздействие разделено на 4 концентрические зоны:

```
┌────────────────────────────────────────────────────────────────────────┐
│  1. ЗЕЛЕНАЯ ЗОНА (Безопасный выпас): Все триггеры OFF                 │
│      └── 2. ЖЕЛТАЯ ЗОНА (15-20м до края): I2S Звук 0.5W (800-2400 Гц) │
│            └── 3. ОРАНЖЕВАЯ ЗОНА (3-5м до края): Звук + ВИБРОМОТОР     │
│                  └── 4. КРАСНАЯ ЗОНА (Пересечение): 400кВ ИМПУЛЬС 150мс│
└────────────────────────────────────────────────────────────────────────┘
```

1. **Ступень 1: Акустическое предупреждение (MAX98357 I2S + Динамик 0.5W)**
   * За 15–20 метров до виртуального забора ошейник синтезирует прерывистый тон.
   * По мере сокращения дистанции до границы частота звука плавно нарастает от 800 Гц до 2400 Гц, а паузы между сигналами сокращаются.
   * Для животного это четкий градиентный сигнал опасности.
2. **Ступень 2: Тактильное раздражение (Вибромотор на шее)**
   * За 3–5 метров до границы включается мощный вибромотор.
   * Вибрация действует непосредственно на кожные рецепторы и мышцы шеи, заставляя животное поднять голову и затормозить шаг.
3. **Ступень 3: Статический электро-импульс (Генератор 400 кВ, импульс 150 мс)**
   * При физическом выходе за периметр срабатывает кратковременный высоковольтный импульс.
   * Это не опасный ток из электросети, а кратковременный статический разряд (по аналогии с традиционным проволочным электропастухом), вызывающий резкое рефлекторное отпрядывание назад.
4. **Результат:** к 4-му дню 98% стада разворачиваются исключительно по звуку, не доходя до вибромотора и импульса.

## 🌾 Сценарии практического применения

### 1. Автономный загон без физических изгородей
Пастух на карте обводит полигоном участок (например, 50 гектаров) со сложным рельефом, оврагами или берегом реки. Животные свободно пасутся внутри контура, не вытаптывая соседние посевы и не выходя на автотрассы.

### 2. Динамический ротационный выпас (Smart Grazing)
Когда трава на участке истощается, фермер на сайте просто перетаскивает полигон пастбища на 200 метров вперед. Ошейники на задней границе начинают подавать звуковые сигналы, плавно подталкивая все стадо на свежий травостой без использования собак и верховых пастухов.

### 3. Виртуальный коридор («На водопой / В кошару»)
Активируется узкая полоса земли, ведущая к источнику воды или ночному загону. Все зоны слева и справа закрыты запретом. Животные идут строго по коридору.

### 4. Управление через вожаков стада (Alpha-Herding)
Для оптимизации затрат не требуется оснащать электрошоковыми модулями каждую голову в многосотенном стаде:
* В стаде овец (100–300 голов) или табуне лошадей выделяются **3–5 альфа-особей (вожаков)**.
* Ошейники с полным комплектом (GPS + Звук + Вибро + Импульс) надеваются на них.
* Рядовые животные снабжаются легкими GPS-трекерами или идут за вожаками стадным инстинктом: когда вожак слышит предупреждение и разворачивается, за ним поворачивает вся отара.

## 🛡️ Безопасность скота и Fail-Safe защита

В прошивке ESP32 реализованы жесткие алгоритмы предотвращения травм и паники:

1. **Аппаратный таймер удара (150 мс):**  
   Импульс 400кВ физически ограничен окном в 150 мс (`SHOCK_DURATION_MS = 150`). Залипание ключа программно заблокировано.
2. **Пауза остывания (Cooldown 6000 мс):**  
   После одного разряда повторный импульс заблокирован минимум на 6 секунд, чтобы дать животному время спокойно сделать шаг назад.
3. **Лимит серии (Max 3 импульса):**  
   Если скот не вернулся после 3 импульсов подряд, высоковольтный блок полностью отключается. Это предотвращает пытку животного, если оно застряло в кустах, канаве или упало.
4. **Режим защиты от паники (Anti-Panic / Stampede Escape):**  
   Если датчик скорости фиксирует бег животного свыше 15 км/ч (нападение волков, гроза, испуг) или удаление от забора более чем на 100 метров — все удары током **полностью блокируются**, а на экран пастуха выводится красная тревога *«ЧП: Побег стада / Возможно нападение хищников»*.
5. **Режим обучения (Training Mode):**  
   Первые 3 дня 400кВ блок отключен в настройках, скот обучается ассоциировать звук и вибрацию с ошейником.

## 🔌 Таблица распиновки ESP32-WROVER и электросхема

> ⚠️ **КРИТИЧЕСКИ ВАЖНО ДЛЯ ESP32-WROVER:**  
> Пины **GPIO 16 и GPIO 17** внутри модуля WROVER подключены к микросхеме SPI PSRAM. Их **категорически нельзя** использовать под GPS, зуммер или другие датчики, иначе микроконтроллер немедленно уходит в циклическую перезагрузку (`Guru Meditation Error`). GPS выведен на безопасные пины **GPIO 32 и 33**.

### Сводная таблица подключений

| Модуль / Периферия | Пин модуля | Пин ESP32-WROVER | Примечание |
| :--- | :--- | :--- | :--- |
| **GPS (NEO-6M / ATGM336H)** | TX | **GPIO 32** (RX2) | Прием NMEA координат |
| | RX | **GPIO 33** (TX2) | Передача команд (опционально) |
| | VCC | 3.3V или 5V | Питание модуля |
| | GND | GND | Общая земля |
| **I2S Усилитель (MAX98357)** | BCLK (Bit Clock) | **GPIO 26** | Тактирование I2S шины |
| | LRC (Word Select) | **GPIO 25** | Выбор левого/правого канала |
| | DIN (Data In) | **GPIO 22** | Поток аудио-данных DMA |
| | GAIN | Не подключать (Float) | Коэффициент 9dB (идеально для 0.5W) |
| | SD (Shutdown) | Не подключать | Всегда активен |
| | VIN | 5V | Питание усилителя |
| | GND | GND | Общая земля |
| **Динамик 0.5W** | Клемма (+) | MAX98357 **OUT+** | Мостовой выход BTL (не сажать на GND!) |
| | Клемма (-) | MAX98357 **OUT-** | Мостовой выход BTL (не сажать на GND!) |
| **Вибромотор** | База транзистора | **GPIO 27** | Через резистор 1 кОм (база NPN S8050) |
| | Коллектор / Дроссель | Мотор (-) | Параллельно мотору диод 1N4148 катодом к 3.3V |
| | Эмиттер транзистора | GND | Общая земля |
| **Генератор импульсов 400 кВ** | Затвор (Gate) MOSFET | **GPIO 19** | Через 1 кОм + стяжка 10 кОм на GND |
| | Сток (Drain) MOSFET | Модуль 400кВ (-) | Силовая коммутация минуса |
| | Исток (Source) MOSFET | GND | Силовая земля |
| | Питание 400кВ (+) | Аккумулятор (3.7V - 5V) | Питать от силовой шины через конденсатор 470 мкФ |
| | Электроды разряда | Шея животного | **Искровой зазор строго 10–12 мм!** |

## 💻 Прошивка ошейника (Firmware)

Исходный код прошивки расположен в:  
👉 [`firmware/esp32_collar/esp32_collar.ino`](file:///c:/Users/Админ/Desktop/qamqor/firmware/esp32_collar/esp32_collar.ino)

### Ключевые особенности прошивки:
1. **Программный синтез сирены по I2S DMA:**  
   MAX98357 не требует SD-карты или MP3 файлов. Звуковой свип-сигнал (FM-сирена 800–2400 Гц) генерируется микроконтроллером на лету с прямой записью в кольцевой DMA буфер I2S шины.
2. **Неблокирующий цикл управления (`millis()`):**  
   Звук, мигание светодиода, таймеры вибромотора и импульса работают без вызовов `delay()`, что обеспечивает мгновенный отклик на сетевые пакеты.
3. **Indoor / Fallback режим:**  
   Если ошейник тестируется в помещении (где нет сигнала спутников GPS), устройство не зависает в цикле ожидания, а отправляет тестовый пинг со статусом и принимает команды удаленного включения звука, вибро и шокера с сайта.

### Инструкция по прошивке через Arduino IDE:
1. Откройте файл `firmware/esp32_collar/esp32_collar.ino`.
2. В меню **Инструменты (Tools) $\rightarrow$ Плата (Board)** выберите **ESP32 Wrover Module**.
3. Настройки платы:
   * **PSRAM:** `Enabled`
   * **Upload Speed:** `921600`
   * **Flash Frequency:** `80MHz`
   * **Core Debug Level:** `None` (или `Info` для отладки)
4. Укажите ваши Wi-Fi параметры в строках:
   ```cpp
   const char* WIFI_SSID     = "BB";
   const char* WIFI_PASSWORD = "Student111";
   ```
5. Нажмите **Загрузить (Upload)**.

## 📡 Протокол взаимодействия (API Telemetry & Trigger)

### 1. Отправка телеметрии ошейником (Каждые 5-300 сек)
* **Эндпоинт:** `POST https://qamqor-api.onrender.com/api/v1/device/telemetry`
* **Тело запроса (ESP32 JSON Payload):**
```json
{
  "deviceId": "QAM-0001",
  "timestamp": "2026-11-04T12:00:00.000Z",
  "latitude": 43.650123,
  "longitude": 51.157245,
  "accuracy": 4.5,
  "battery": 92,
  "signal": -68
}
```
* **Ответ сервера (Команды исполнительным механизмам):**
```json
{
  "success": true,
  "serverTime": "2026-11-04T12:00:01.250Z",
  "nextInterval": 60,
  "inFence": false,
  "sound": true,
  "vibrate": true,
  "shock": true,
  "shockDurationMs": 150,
  "buzzer": true,
  "warningMessage": "⚠️ ВНИМАНИЕ: Животное покинуло безопасную зону! Активированы все защитные триггеры."
}
```

### 2. Ручное управление триггерами с веб-панели
* **Эндпоинт:** `POST https://qamqor-api.onrender.com/api/v1/device/trigger`
* **Тело запроса:**
```json
{
  "deviceId": "QAM-0001",
  "sound": true,
  "vibrate": false,
  "shock": false
}
```
* **Сброс всех тревог:**
```json
{
  "deviceId": "QAM-0001",
  "reset": true
}
```

### 3. Проверка онлайн-статуса и датчиков ошейника
* **Эндпоинт:** `GET https://qamqor-api.onrender.com/api/v1/device/status`
* Ошейник считается **ONLINE**, если от него приходил пинг в течение последних 45 секунд. Если пингов нет — статус автоматически переключается в **OFFLINE** с указанием секунд с момента последней связи.

### Функционал экрана управления:

## 🏗️ Архитектура репозитория и быстрый запуск

```text
qamqor/
├── apps/
```

### Локальный запуск проекта:

1. **Установка зависимостей:**
   ```bash
   pnpm install
   ```
2. **Сборка общих библиотек:**
   ```bash
   pnpm --filter @qamqor/shared run build
   pnpm --filter @qamqor/contracts run build
   ```
3. **Запуск Backend API (порт 4000):**
   ```bash
   pnpm dev:api
   ```
4. **Запуск Frontend Dashboard (порт 3000):**
   ```bash
   pnpm dev:web
   ```
