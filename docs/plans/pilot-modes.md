# План: режимы данных «Реальный / Ручной (пилот) / Авто (симуляция)»

Связанные документы: [../architecture/api-contract.md](../architecture/api-contract.md), [PLAN.md](PLAN.md), [backend-hardening.md](backend-hardening.md).

Запрос владельца: у сайта и приложения должны быть режимы. «Пилот» — всё вводится вручную (позиция животного, статус, события) для показа системы на презентации. «Авто» — сервер сам шлёт данные по сценарию, отражающему суть проекта (выпас, приближение к виртуальной границе, звук, затем вибрация, побег, оповещения, потеря связи). Настоящие ESP32 продолжают работать.

## 0. Факты, допущения, рекомендации

**Проверено по коду (2026-11-09):**
- Единый конвейер телеметрии: `TelemetryService.processDeviceTelemetry(device, dto)` (`server/src/telemetry/telemetry.service.ts`). Он считает зону через `GeofenceService.evaluateLocation` (GREEN > 20 м от границы, YELLOW 5–20 м, ORANGE < 5 м, RED снаружи ≤ 100 м, ESCAPE > 100 м или скорость > 15 км/ч, UNKNOWN при точности хуже 35 м), применяет суточные лимиты сигналов, создаёт оповещения (`GEOFENCE_BREACH`, `GEOFENCE_RETURN`, `GPS_LOST`, `DEVICE_RESTORED`), пишет `Telemetry` и кэш позиции в `Animal`. Принимает время в окне [−600 с, +120 с] от «сейчас», повтор `(deviceId, timestamp)` не пишется, пинг не новее `lastSeenAt` не двигает животное.
- `OfflineWatcherService` (setInterval раз в 60 с, advisory lock 727301 внутри транзакции) создаёт `DEVICE_OFFLINE` для ошейников, молчащих дольше 900 с (3 x 300 с). Комментарий в коде: запись вне `tx` внутри транзакции с lock'ом даёт взаимную блокировку при `connection_limit=1`.
- `Device.isSimulated` уже есть в схеме и выбирается в `COLLAR_SELECT`, но в `CollarDto` не отдаётся. Секрет симулированного ошейника случайный и нигде не сохраняется (хеш), поэтому по HTTP он пинговать не может; настоящий ошейник и симуляция не пересекаются.
- Есть dev-only `MockModule` (`/api/v1/mock/*`, права W, не подключается при `NODE_ENV=production`). Он вызывает тот же `processDeviceTelemetry`, но: нет метки «демо» в данных, нет режима в ферме, захардкожены координаты Актау (43.65, 51.157), в production недоступен. В `site/` и `app/` вызовов `/mock` нет (grep).
- Роли: `@FarmRoles('OWNER')` + `FarmAccessGuard` (`x-farm-id`). Маршруты `/farms/:id/...` проверяют роль в сервисе.
- Rate limit: `SlidingWindowLimiter` в памяти (`server/src/common/rate-limit.ts`).
- Сайт: карта (`site/src/app/views/map.ts`) опрашивает `/animals` раз в 30 с; настройки — `views/settings.ts`; i18n — `site/src/locales/app.ts`; тексты kk/ru/en.
- Приложение: `app/src/screens/MapScreen.tsx` не использует картографическую библиотеку (только View/Text), приложение пока не приведено к контракту (api-contract.md §0).
- Деплой: `render.yaml` запускает `prisma migrate deploy` при старте; одна инстанция (Render free).
- Последняя миграция: `0011_lower_emails`, следующая — `0012`.

**Допущения (проверить/измерить на P1):**
- Один пинг = около 8 запросов к БД; 8 животных каждые 10 с укладываются в бесплатный Neon при условии, что симуляция идёт только пока на неё смотрят. Нагрузку измерить.
- Демо-координаты по умолчанию: прямоугольник около 600 x 400 м у Актау (центр 43.650, 51.157), если у фермы нет ни одного загона. Это допущение владельца-по-умолчанию, не факт о его пастбище.
- Казахский вариант слова «Демо» совпадает с русским; kk-строки проверяет носитель.

**Рекомендации (приняты по умолчанию, ниже в плане):**
1. Режим живёт **на ферме** (`Farm.dataMode`), а метка «демо» — **на данных** (`isDemo` у животного, загона, оповещения; `isSimulated` у ошейника). Режим решает, что разрешено и что показывать в шапке; метка на данных решает, что удалить и как подписать. Настоящие ошейники работают в любом режиме, их данные никогда не помечаются демо.
2. Демо и реальное не смешиваются в операциях: симулированный ошейник нельзя привязать к реальному животному, реальный — к демо-животному (409).
3. Ручной ввод и симулятор идут через тот же `processDeviceTelemetry`, а не пишут в БД напрямую: демо проверяет настоящую логику зон, лимитов и оповещений.
4. Статус животного **вычисляется** (api-contract.md), поэтому «задать статус» вручную = вызвать событие, которое меняет условия (выход за границу, потеря связи, плохой GPS). Прямой записи статуса нет: это был бы фальшивый функционал.

## 1. Режимы

| `dataMode` | Смысл | Демо-данные | Ручные вызовы | Симулятор |
|---|---|---|---|---|
| `REAL` (по умолчанию) | только настоящие ошейники | нет (при переключении сюда демо-данные **удаляются**) | 409 | выключен |
| `MANUAL` | пилот: владелец сам ставит животных и запускает события | есть | разрешены (O) | выключен |
| `AUTO` | сервер ведёт демо-стадо по сценарию | есть | 409 («остановите симуляцию») | работает |

Переходы: `REAL -> MANUAL|AUTO`, `MANUAL <-> AUTO` (демо-данные сохраняются), `MANUAL|AUTO -> REAL` (удаление демо-данных, подтверждение в UI). Менять режим может только владелец; работник видит режим и демо-данные.

Переменная окружения `DEMO_MODES_ENABLED` (по умолчанию `true`): при `false` маршруты симуляции отвечают 404, а симулятор не стартует. Предохранитель на случай, если демо-режимы нужно убрать с боевой фермы.

## 2. Модель данных (миграция `0012_demo_modes`)

```prisma
enum DataMode { REAL MANUAL AUTO }

model Farm {
  dataMode      DataMode  @default(REAL)
  simSpeed      Int       @default(1)   // множитель скорости сценария: 1, 2, 5, 10
  simHerd       Int       @default(8)   // число демо-животных, 1..20
  simUntil      DateTime?               // автостоп симуляции
  simLeaseUntil DateTime?               // аренда тика, см. 4.2
}
model Animal   { isDemo Boolean @default(false) }
model Geofence { isDemo Boolean @default(false) }
model Alert    { isDemo Boolean @default(false) }
```

- Все колонки с `DEFAULT`, существующие строки получают `REAL`/`false`: миграция обратимо-совместима, данные не трогаются.
- Миграция генерируется **без БД**: `npx prisma migrate diff --from-schema-datamodel <схема из git HEAD> --to-schema-datamodel prisma/schema.prisma --script > prisma/migrations/0012_demo_modes/migration.sql` (схему HEAD сохранить во временный файл вне репозитория). Ручная проверка SQL: `CREATE TYPE`, пять `ADD COLUMN`. Частичный уникальный индекс из `0007_alert_dedupe` в схеме не описан и в diff попасть не должен (проверить, что `DROP INDEX` отсутствует).
- `Telemetry` и `SignalEvent` без колонок: они удаляются каскадом через демо-ошейник/демо-животное. Индексы по `isDemo` не нужны (таблицы малы, допущение).
- `AlertsService` выставляет `isDemo` в единственном месте создания оповещения по `animal.isDemo` (проверить при реализации, что другого пути создания нет).
- Уведомления: сейчас внешних уведомлений о тревогах нет (почта только для приглашений и сброса пароля). Правило на будущее: оповещения с `isDemo` никогда не отправляются наружу.

## 3. Контракт API (добавления к api-contract.md)

Типы: `FarmDto += dataMode`; `AnimalDto`, `PenDto`, `CollarDto`, `AlertDto += isDemo: boolean`. `isDemo` у ошейника = `Device.isSimulated`.

Новые эндпоинты (все с `:id` фермы, права проверяются в сервисе, как у `/farms/:id/signal-limits`):

| Метод и путь | Права | Запрос | Ответ |
|---|---|---|---|
| `GET /farms/:id/simulation` | W | — | `SimulationDto` (ниже); одновременно отмечает «ферму смотрят» (см. 4.3) |
| `PUT /farms/:id/data-mode` | O | `{mode: 'REAL'\|'MANUAL'\|'AUTO'}` | `SimulationDto`; `AUTO` запускает симулятор с текущими `simSpeed/simHerd`, `simUntil = now + 2 ч`; `REAL` удаляет демо-данные |
| `POST /farms/:id/simulation/start` | O | `{speed?: 1\|2\|5\|10, herd?: 1..20, hours?: 1..8}` | `SimulationDto`; то же, что `PUT AUTO`, с параметрами |
| `POST /farms/:id/simulation/stop` | O | — | `SimulationDto` (режим `MANUAL`, демо-данные остаются) |
| `POST /farms/:id/simulation/reset` | O | — | `SimulationDto`; удаляет демо-оповещения, телеметрию и события сигналов, возвращает демо-животных в центр загона, закрывает состояние сценария |
| `PATCH /farms/:id/simulation` | O | `{speed?}` | `SimulationDto` (смена скорости на лету) |
| `POST /farms/:id/simulate/animals` | O | `{name?, species?}` (режим MANUAL) | `AnimalDto` (демо-животное + симулированный ошейник `QAM-DEMO-xxxx`, привязка к загону; не больше 20 демо-животных на ферму) |
| `POST /farms/:id/simulate/telemetry` | O | `{animalId, lat, lng, accuracyM?(по умолчанию 5), speedKmh?}` (режим MANUAL) | `CollarResponseDto`: `{zone, inFence, distanceToBorderMeters, sound, vibrate, toneFrequencyHz, suppressedBy}` — то есть то, что получил бы ошейник |
| `POST /farms/:id/simulate/events` | O | `{animalId, event}` (режим MANUAL) | `CollarResponseDto \| {ok: true}` |

События `event`:
- `BREACH` — точка в 30 м снаружи ближайшей границы (зона RED: звук и вибрация, `GEOFENCE_BREACH`);
- `ESCAPE` — точка в 150 м снаружи (зона ESCAPE: сигналы отключены, защита от паники);
- `RETURN` — точка внутри загона дальше 20 м от границы (`GEOFENCE_RETURN`);
- `GPS_LOST` — пинг с точностью 80 м (зона UNKNOWN, `GPS_LOST`);
- `COLLAR_OFFLINE` — `lastHeartbeatAt` ошейника сдвигается на `порог + 60 с` назад и вызывается `OfflineWatcherService.tick()` (создаёт `DEVICE_OFFLINE` настоящей логикой, а не прямой записью);
- `COLLAR_ONLINE` — пинг в последней позиции (`DEVICE_RESTORED`).

```ts
interface SimulationDto {
  dataMode: 'REAL' | 'MANUAL' | 'AUTO';
  running: boolean;              // AUTO и до simUntil
  speed: 1 | 2 | 5 | 10; herd: number;
  until: string | null;          // ISO, автостоп
  demo: { animals: number; alerts: number };
  enabled: boolean;              // DEMO_MODES_ENABLED
}
```

Ошибки: `CONFLICT` при вызове не в том режиме или привязке демо к реальному; `FORBIDDEN_ROLE` для работника; `NOT_FOUND` для чужого/не демо животного (ручные вызовы работают **только** с `isDemo` животными и `isSimulated` ошейниками); `VALIDATION` для координат вне диапазона и `herd/hours` вне границ.
Лимит запросов: ручные вызовы 60 в минуту на пользователя (`SlidingWindowLimiter`).

`MockModule` и `/mock/*` удаляются после P1 (их заменяет `simulate/*`; вызовов в клиентах нет, повторный grep перед удалением). Строка «Симулятор» в api-contract.md §3 переписывается.

## 4. Автосимулятор (сервер)

### 4.1 Состав
Новый `SimulationModule` (в `AppModule` всегда, не только dev): `SimulationService` (режимы, демо-данные, ручные вызовы, очистка), `SimulatorService` (планировщик и сценарий, по образцу `OfflineWatcherService`: `setInterval(...).unref()`, выключается при `schedulerEnabled=false` и в тестах). Использует `TelemetryService`, `GeofenceService`, `OfflineWatcherService`, `AlertsService`. Новых зависимостей нет: ГСЧ `mulberry32` пишется в коде.

### 4.2 Планировщик и стоимость
- Тик каждые `SIM_TICK_SEC` (по умолчанию 10 с). За тик: выбрать фермы с `dataMode = AUTO`, `simUntil > now`, не заблокированные арендой; для каждой — один проход по демо-животным **последовательно** (без параллелизма, чтобы не занимать пул).
- Аренда вместо advisory lock: `UPDATE farms SET simLeaseUntil = now()+interval '30 s' WHERE id = $1 AND (simLeaseUntil IS NULL OR simLeaseUntil < now())`; обработка идёт, только если обновилась 1 строка. Причина отклонения от `OfflineWatcher`: тот держит lock внутри транзакции и пишет через `tx`, а пинги идут через общий клиент и при `connection_limit=1` заблокировали бы друг друга. Корректно и для нескольких инстанций.
- **«Пока на симуляцию смотрят»:** `GET /farms/:id/simulation` обновляет в памяти `lastViewedAt`. Если с него прошло больше 3 мин, тик пропускает ферму (БД не пишется, Neon может заснуть). Сайт опрашивает этот эндпоинт каждые 15 с, пока вкладка видима.
- Автостоп: при `simUntil <= now` ферма переводится в `MANUAL` (демо-данные остаются). По умолчанию 2 ч, максимум 8 ч.
- Ограничение строк: `Telemetry` демо-ошейников старше 30 мин, `SignalEvent` старше 2 ч и решённые демо-`Alert` старше 1 ч удаляются раз в 5 мин в том же проходе; демо-оповещений не больше 200 на ферму (старейшие решённые удаляются). Итог: порядка 8 x 180 = 1440 точек телеметрии в пике.
- Скорость сценария `speed` меняет длину шага и скорость смены фаз, а **не** частоту записей: нагрузка на БД не растёт.

### 4.3 Состояние и инициализация
Состояние сценария (фаза, курс, счётчики) хранится в памяти по `farmId/animalId`; после перезапуска сервера восстанавливается из `Animal.lastLatitude/lastLongitude` в фазе GRAZE (допущение: потерять фазу сценария при перезапуске допустимо). При старте симулятор создаёт недостающих демо-животных до `simHerd` (имена из короткого списка в коде, номера `D-001…`, виды CATTLE), симулированные ошейники и, если у фермы нет загона, демо-загон «Демо-пастбище» (`isDemo = true`). Если загон есть, используется самый старый, демо-животные ходят внутри него (проверка точки через `GeofenceService.isPointInPolygon`, так что невыпуклые загоны допустимы).

### 4.4 Сценарий (цикл примерно 6 мин при speed 1, фазы разведены по животным)
1. `GRAZE` — случайное блуждание с инерцией курса, шаг до 5 м за тик, остаётся внутри загона (отражение от границы, отбор точек через point-in-polygon). Зона GREEN, сигналов нет.
2. `APPROACH` — курс смещается к ближайшему участку границы: GREEN → YELLOW (звук) → ORANGE (звук и вибрация). Сигналы создаёт настоящая логика зон.
3. Развилка (ГСЧ с зерном, 70 / 30): `TURN_BACK` — «животное отреагировало на сигнал», разворот внутрь и возврат в `GRAZE`; или `BREAKOUT` — пересечение границы: RED, `GEOFENCE_BREACH` (CRITICAL), затем ESCAPE на 100+ м (сигналы выключены, интервал аварийный), затем `HERDED_BACK` — возврат внутрь с `GEOFENCE_RETURN`.
4. Событийные вставки, не чаще одной каждого вида за 8–10 мин на ферму: `GPS_LOST` (2 пинга с точностью 60–80 м), `OFFLINE` (животное не пингуется 2 минуты реального времени, `lastHeartbeatAt` сдвигается назад на порог, вызывается `OfflineWatcherService.tick()`, затем `DEVICE_RESTORED`). Честная оговорка: порог настоящей тревоги 15 мин сжат до 1–2 мин **только** для демо и подписан в описании фазы.
5. Суточные лимиты сигналов действуют как у настоящих животных; при исчерпании появляется `SIGNAL_LIMIT_REACHED`. Это нормальное поведение системы, его не отключаем.

Один раз за запуск сценарий гарантирует показ всех ключевых событий в первые 3–4 мин (первое животное сразу идёт в APPROACH → TURN_BACK, второе — в BREAKOUT), чтобы презентация не ждала случая.

## 5. Фазы

### P1. Сервер (backend-engineer, после независимого ревью плана)
Работы: миграция `0012`; `DataMode` и `isDemo` в DTO/мапперах; `SimulationModule` (режимы, демо-данные, ручные вызовы, очистка при `REAL`); `SimulatorService` со сценарием; метка `isDemo` у оповещений; запрет смешивания демо и реального при привязке ошейника; удаление `MockModule`; обновление api-contract.md и `.env.example` (`DEMO_MODES_ENABLED`, `SIM_TICK_SEC`).
Критерии приёмки:
- [ ] `prisma migrate diff` даёт ровно ожидаемый SQL; `migrate deploy` на пустой и на копии существующей БД проходит; `DROP INDEX` отсутствует; существующие фермы имеют `REAL`.
- [ ] Юнит/интеграционные тесты (jest, одноразовая БД, не боевая): переходы режимов и права (работник → `FORBIDDEN_ROLE` на мутациях, `GET` доступен); ручной `BREACH` даёт RED, `GEOFENCE_BREACH`, `sound` и `vibrate`; `RETURN` даёт `GEOFENCE_RETURN`; `GPS_LOST` и `COLLAR_OFFLINE/ONLINE` создают и закрывают соответствующие оповещения; ручной вызов к реальному животному → 404; в `REAL` и в `AUTO` ручные вызовы → 409.
- [ ] Тест сценария на фиксированном зерне: за N тиков встречаются зоны GREEN, YELLOW, ORANGE, RED, ESCAPE, оповещения BREACH, RETURN, GPS_LOST, OFFLINE, RESTORED; все точки GRAZE внутри полигона (в том числе на невыпуклом).
- [ ] Тест ограничений: после имитации 3 ч телеметрия демо ≤ лимита, оповещений ≤ 200; нет «подвисшей» аренды; ферма без просмотра > 3 мин не пишет в БД; автостоп переводит в `MANUAL`.
- [ ] Переход в `REAL` удаляет демо-животных, ошейники, загон, оповещения, телеметрию и события сигналов и **не** трогает реальные записи (тест с реальным животным и ошейником в той же ферме).
- [ ] Реальный `POST /device/telemetry` работает в `MANUAL` и `AUTO` без изменений; данные реального ошейника с `isDemo = false`.
- [ ] `npm run build` и `npm test` зелёные; `git status` проверен; измерение: число запросов на тик и время тика при 8 и 20 животных записано в отчёт (допущение из раздела 0 подтверждено или исправлено).

### P2. Панель сайта (сначала бриф ui-designer в `docs/frontend/pilot-modes-brief.md` и его ревью; затем frontend-engineer)
Бриф обязателен (визуальное изменение). Состав экранов:
- **Шапка приложения:** постоянная полоса при `dataMode != REAL`: «Демо · ручной режим» или «Демо · симуляция, не настоящие животные» (`role="status"`, текст + иконка, не только цвет).
- **Настройки → «Режим данных»** (владелец; работник видит режим без переключателя): три варианта (радио) с описанием; переход в `REAL` через диалог подтверждения («демо-данные будут удалены»), по `ui/dialog.ts` (Esc, focus trap, возврат фокуса).
- **Карта → «Демо-панель»** (владелец, при `MANUAL`/`AUTO`), в боковой панели/листе:
