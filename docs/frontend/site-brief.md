# Qamqor: дизайн-бриф сайта (лендинг + веб-кабинет)

Источники: запрос владельца 2026-11-08; [../requirements.md](../requirements.md); [app-design-brief.md](app-design-brief.md) (утверждённый язык A3, токены, правила копирайта п. 9); [../research/chatgpt-concept-2026-11-08.md](../research/chatgpt-concept-2026-11-08.md) (непроверенный материал: берём только то, что подтверждено другими документами); [../architecture/api-contract.md](../architecture/api-contract.md); [../../hardware/enclosure/README.md](../../hardware/enclosure/README.md); STL в `hardware/3d-models/` (измерено скриптом, см. п. 2.2).

Сайт это одно приложение, которое раздаёт наш сервер: публичный лендинг и кабинет за входом. Стек утверждён: Vite, three.js, MapLibre, больше ничего (CLAUDE.md §3.5: новые зависимости только с согласия). Шрифты свои, без CDN.

Контраст в документе посчитан по формуле WCAG 2.x скриптом, а не на глаз. Размеры: px = CSS px, если не оговорено.

## 0. Что решено, что допущено, что нужно владельцу

**Допущения (внёс я, помечены в тексте):**

1. Размеры. Владелец просит «210 × 80 × 90 мм». В README корпуса: корпус 194 × 80, ушки ремня дают 210 по длине; закрытый габарит с петлёй и защёлками 210 × 89 × 90. Показываем **210 × 80 × 90 мм** как просили, с примечанием «80 мм: ширина корпуса вдоль шеи; с петлёй и защёлками глубина до 89 мм». Это не противоречие, а две разные ширины; примечание обязательно.

3. Сторона «слева» это −X в системе STL (README, допущение 3 корпуса).
4. Ступени сигнала «звук, затем вибрация» взяты из requirements (§2, помечено как допущение, для нового железа не подтверждено). Формулировать как замысел («задуман»), не как факт испытаний. Прошу `content-guard` проверить.
5. Положение панели по оси Y принято 0 (в README задан только x = −20).

## 1. Визуальный язык

Основа: A3 «Горизонт современный» (хвойно-зелёный против тёпло-белого, один сигнальный цвет, Inter, тональные блоки вместо рамок, стекло с бликом). Для лендинга добавлена **тёмная ночная ступень** той же зелёной семьи. Лендинг: ночь (сцены с моделью) чередуется со светом (описательные блоки). Кабинет: светлая тема A3 без изменений.

Что делает его «презентацией уровня keynote», проверяемо:

- Одна идея на экран. Крупный заголовок, одно предложение, одна подпись. Не больше 25 слов текста на сцену.
- Модель всегда главный объект сцены (занимает 38 до 48 % ширины окна на десктопе), текст рядом, не поверх.
- Движение привязано к прокрутке и обратимо (прокрутка назад отматывает).
- Много воздуха: вертикальные поля секций 120 до 200 px на десктопе.

Антипаттерны (из CLAUDE.md §6 и A3): фиолетово-синие градиенты, три одинаковые карточки в ряд, иконки в цветных кругах, нумерация 01/02/03, заглавные «надстрочные» подписи (eyebrow), пилюли везде, неон, стоковые фото, ИИ-картинки людей и коров. Фон тёмных сцен: глубокий зелёный, не чёрный и не синий.

### 1.3 Стекло (рецепт и запасные варианты)

Стекло только у: шапки лендинга, карточек характеристик на ночи, подписей-выносок к модели, нижней карточки текста сцены на мобильном, панели кабинета на карте. Не на строках и не на кнопках.

Тёмное:

```css
.glass-dark {
  background: linear-gradient(rgba(255,255,255,.06), rgba(255,255,255,.06)), rgba(6,20,13,.58);
  backdrop-filter: blur(24px) saturate(1.4);
  border-radius: 20px;
  box-shadow:
    inset 0 1px 0 rgba(255,255,255,.28),      /* верхний край */
    inset 0 0 0 1px rgba(255,255,255,.14),    /* контур */
    0 18px 48px rgba(0,0,0,.35);
}
.glass-dark::before { /* блик */
  content: ""; position: absolute; inset: 0 0 auto 0; height: 96px; border-radius: inherit; pointer-events: none;
  background: radial-gradient(120% 100% at 50% 0, rgba(255,255,255,.18), transparent 70%);
}
```

Светлое: заливка `rgba(246,250,244,.86)`, `blur(28px) saturate(1.5)`, внутренний свет и блик как в A3 п. 2.4 (`rgba(255,255,255,.95)`, `.75`).

Запасные варианты (обязательны, проверяются):

| Условие | Поведение |
|---|---|
| `@supports not (backdrop-filter: blur(1px))` | тёмное: сплошной `night-2` `#0F2F1F` (snow на нём 13.45, mist-2 9.21), светлое: `surface-0` |
| `@media (prefers-reduced-transparency: reduce)` | то же, сплошные цвета, блики остаются |
| слабое устройство (watchdog п. 4.5 перешёл в режим «лёгкий») | сплошные цвета, `backdrop-filter: none` |
| `@media (forced-colors: active)` | стекло заменяется `Canvas` с границей `CanvasText` 1 px; модель остаётся, линии размеров `CanvasText` |
| печать | фон белый, сцены идут по порядку, модель заменена статичным постером |

## 2. Модель ошейника

### 2.1 Подготовка (результат работы инженера, не дизайнера)

Исходники: `hardware/3d-models/qamqor_base.stl` и `qamqor_lid.stl` (ASCII STL, 2,07 МБ и 0,69 МБ). Файл плиты `qamqor_plate_bambu_256.stl` не использовать (там детали разложены для печати, крышка перевёрнута).

Измерено по файлам (координаты сборки, Z вверх, мм):

| Деталь | Треугольников | Уникальных вершин | X | Y | Z |
|---|---|---|---|---|---|
| основа | 11 508 | 5 540 | −105,0…105,0 | −41,2…47,9 | 0…73,8 |
| крышка | 3 816 | 1 900 | −97,0…97,0 | −46,5…47,9 | 56,0…90,0 |

Обе детали в общей системе координат сборки, крышка перекрывает основу по высоте (фланец, защёлки), поэтому их можно класть как есть.

Конвейер (скрипт `site/scripts/stl-to-glb.mjs` на чистом Node без зависимостей, пишет GLB сам):

1. Прочитать ASCII STL, склеить вершины (допуск 0,001 мм), получить индексированную сетку.
2. Квантовать позиции в `Int16` (расширение `KHR_mesh_quantization`, масштабирование в матрице узла), индексы `Uint16`. Нормали в файл не писать: считаются при загрузке через `toCreasedNormals(geometry, 0.52)` (угол 30°) из `BufferGeometryUtils` three.js, на 15 тыс. треугольников это меньше 20 мс. Так плоские фланцы и скругления шейдятся правильно.
3. Два узла `base` и `lid` с общим началом координат. Центр вращения: `(0, 0, 45)` мм (середина по высоте).
4. Ожидаемый размер: позиции 7,4 тыс. вершин × 6 Б ≈ 45 КБ, индексы 15,3 тыс. × 3 × 2 Б ≈ 92 КБ, итого около 140 КБ сырой GLB, около 60 КБ после Brotli сервера. Draco и Meshopt **не нужны** и не используются: модель мала, декодеры только увеличили бы бандл.
5. Оценка размера: вес файла и число треугольников выводит скрипт; порог сборки 400 КБ сырой GLB, при превышении сборка падает.

Если инженер предпочитает готовый конвертер, это новая зависимость и нужно согласие владельца (CLAUDE.md §3.5). Рекомендация: свой скрипт, он короткий.

### 2.2 Материалы и свет

Единицы сцены: 1 единица = 100 мм. Модель масштабируется на 0,01, сдвигается так, чтобы `(0, 0, 45)` мм был началом координат группы, поворачивается на −90° вокруг X (Z вверх → Y вверх). После этого: длина вдоль X, верх с крышкой вверх (+Y), лицо с защёлками (−Y STL) смотрит на камеру (+Z), левый бок со звуковой решёткой (−X) слева, петля и окно USB сзади.

| Объект | Материал `MeshStandardMaterial` |
|---|---|
| основа и крышка | цвет `#141816`, `roughness 0.82`, `metalness 0.0`, `envMapIntensity 0.9`. Матовый чёрный; блеск только на кромках за счёт контрового света |
| солнечная панель (генерируется) | блок 55 × 55 × 3 мм, центр `x = −20, y = 0`, лежит в нише (верх на Z = 89,5). Цвет `#0B1B2E`, `roughness 0.35`, `metalness 0.4`, текстура-сетка ячеек рисуется в `CanvasTexture` 512 × 512 (линии `#2A4A6A`, число ячеек декоративное), без файла-картинки |
| окно GPS | сквозное по STL, внутри плоскость `#05100A` на 2 мм ниже верха (не видно «пустоту») |
| подсветка панели (сцена 2) | `emissive #7FD6A0`, `emissiveIntensity` 0 → 0,35 на сцене 2, возврат к 0 к сцене 3 |

Теней нет. «Контактная тень» это плоскость с радиальным градиентом (CanvasTexture 128 × 128, `opacity .45`), лежит ниже модели на 1,05 единицы, масштабируется вместе с моделью. Тон-маппинг `ACESFilmic`, экспозиция 1.0, `outputColorSpace sRGB`.

Камера: `PerspectiveCamera`, вертикальный угол 28°, `near 0.1`, `far 40`, смотрит в начало координат (цель смещается только по y для мобильного). Фон канвы прозрачный (фон даёт CSS), чтобы градиент был на странице.

## 3. Раскадровка прокрутки

### 3.1 Принцип

Блок-сцена «stage»: родитель высотой **`760svh`** на десктопе (мобильный 640svh), внутри `position: sticky; top: 0; height: 100svh`. Нативная прокрутка, **без перехвата колеса и без библиотек плавной прокрутки**. Прогресс `P = clamp((scrollY − stageTop) / (stageHeight − viewportHeight), 0, 1)`.

Сцены задаются границами `P` и позой. Позы хранятся как кватернионы (интерполяция `slerp`, не по Эйлеру, чтобы не было «кувырков»); для чтения ниже углы Эйлера, порядок `YXZ`, градусы, относительно базовой позы из п. 2.2 (0,0,0 = вид спереди, верх вверх).

Переходы: между сценами окно смешивания ±0,03 по `P` вокруг границы, функция `smootherstep`. Внутри сцены поза «дрейфует» (медленно меняется), чтобы модель не замирала.

Сглаживание: целевое значение берётся из `P`, фактическое догоняет критически демпфированной пружиной (`k = 9 1/с`), без перерегулирования. Это даёт «тяжесть» как в презентациях и убирает рывки колеса.

Текст сцены это обычные `h2`/`p` в DOM, появляются при `P` внутри `[начало + 0,015, конец − 0,015]` с `opacity 0 → 1` и `translateY(24px → 0)` по `smootherstep`; до этого и после `opacity: 0`, но `visibility` остаётся по правилам доступности (п. 5.3).

## 4. Производительность

### 4.1 Бюджет

Бюджет передачи (после Brotli), холодная загрузка 4G (1,6 Мбит/с, 150 мс), цель LCP ≤ 2,5 с на среднем телефоне. Потолок владельца «начальная загрузка около 2,5 МБ»: **наш бюджет значительно жёстче**, потому что всё тяжёлое грузится позже.

| Что | Когда | Бюджет |
|---|---|---|
| HTML лендинга (с встроенным критическим CSS) | сразу | ≤ 20 КБ |
| CSS лендинга | сразу | ≤ 40 КБ |
| JS оболочки (маршрутизатор, переключатель языка, шапка, скролл-логика без three) | сразу | ≤ 60 КБ |
| Шрифт Inter variable, подмножество | сразу (`preload`, `font-display: swap`) | ≤ 150 КБ |
| Постер hero (WebP, `fetchpriority="high"`) | сразу | ≤ 120 КБ |
| **Итого до первого показа** | | **≤ 400 КБ** |
| three.js (импорт только нужных классов, tree-shaking) | после появления постера и `requestIdleCallback` | ≤ 220 КБ |
| Модель GLB | вместе с three.js | ≤ 80 КБ Brotli (сырая ≤ 400 КБ) |
| Снимки макетов в блоке «Платформа» (WebP, ширина до 960, `loading="lazy"`) | при подходе | ≤ 4 × 90 КБ |
| **Итого весь лендинг** | | **≤ 1,3 МБ** (жёсткий потолок 2,5 МБ) |
| MapLibre и код кабинета | только на маршрутах `/app/*` | не входит в лендинг; отдельные чанки |

Проверка: отчёт сборки (размеры чанков) и вкладка Network в Chrome с троттлингом; в отчёте QA числа, а не «быстро».

Метрики (лабораторные, Lighthouse mobile и реальное устройство): LCP ≤ 2,5 с, CLS ≤ 0,05, TBT ≤ 200 мс, INP ≤ 200 мс. FPS в сценах не ниже 50 на ноутбуке с интегрированной графикой, не ниже 30 на среднем телефоне; иначе включается режим «лёгкий» (п. 4.5).

### 4.2 Загрузка

1. Постер hero это изображение той же позы (пока без живой модели): WebP из готового рендера `hardware/enclosure/render/01_assembly_front.png` (или лучше отдельный рендер позы сцены 1, это работа инженера/владельца модели), на фоне CSS-градиента сцены. Постер не ИИ, это реальный рендер STL; подписи не нужно.
2. После события `load` постера и `requestIdleCallback` (запасной вариант `setTimeout 300`) динамический `import('./stage.js')` тянет three.js и GLB параллельно (`fetch` GLB стартует вместе с чанком).
3. Если `navigator.connection.saveData === true` или `effectiveType` в `['slow-2g','2g']`, или устройство с `deviceMemory ≤ 2`: three.js **не грузится**, остаётся режим статичных постеров (п. 5.1).
4. Не грузить three.js, если вкладка в фоне (`document.hidden`): ждать `visibilitychange`.

### 4.3 Рендер

- `WebGLRenderer({ antialias: true, alpha: true, powerPreference: 'high-performance' })`; при DPR ≥ 2 `antialias` выключить (достаточно плотности).
- `setPixelRatio(min(devicePixelRatio, 2))` на десктопе, `min(…, 1.5)` на мобильном.
- Кадры рисуются **только при необходимости**: когда `P` изменился или пружина ещё не успокоилась (порог 0,0005). В покое рендера нет (энергопотребление).
- Цикл остановлен вне зоны блока (`IntersectionObserver`), при `document.hidden`, при потере контекста.
- Один `WebGLRenderer`, одна канва, один материал на деталь, нет теней, нет постобработки, нет `OrbitControls`.
- Освобождение: при уходе со страницы `dispose()` геометрии, материалов, текстур, рендерера.
- `webglcontextlost`: предотвратить `preventDefault`, показать постер, попытаться восстановить при `webglcontextrestored`.

### 4.4 Изображения и шрифты

WebP, ширины 480/960/1440 в `srcset`, `width` и `height` заданы (нет CLS), блоки ниже экрана `loading="lazy" decoding="async"`. Шрифт один, `font-display: swap`, метрики запасного шрифта подогнаны `size-adjust`, `ascent-override` (нет скачка при подмене). Вес шрифта 100 до 900 в одном файле; если размер превышает 150 КБ, подмножество уменьшить (убрать `opsz`).

### 4.5 «Сторож» производительности

Среднее время кадра за 60 кадров подряд > 24 мс: шаг 1: DPR → 1,25, стекло → сплошные цвета; шаг 2: DPR → 1,0, контровой свет упрощается (без PMREM, только прямые источники); шаг 3: режим статичных постеров (п. 5.1) с короткой плашкой «Включён упрощённый режим» и ссылкой «Включить анимации» (после ручного включения сторож не вмешивается). Состояние хранится в `localStorage` (с `try/catch`, страница работает и без него).

## 5. Движение, доступность, отказоустойчивость

### 5.1 `prefers-reduced-motion: reduce`

Принцип: **ничего не движется по прокрутке; информация та же**. Пиннинга нет, `stage` не высокий, сцены идут обычными блоками друг за другом.

- Каждая сцена: блок `min-height: auto`, две колонки (текст, изображение) от 900 px, одна колонка ниже; изображение это **статичная поза** сцены (таблица 3.2, конечные значения без дрейфа; для сцены 5 `e = 1`; для сцены 6 линии размеров нарисованы).
- Получение изображений: после загрузки three.js модель один раз рендерится в `RenderTarget` по очереди во все 6 поз и сохраняется в `<img>` (через `canvas.toBlob`, WebP 0,85, около 1280 × 960); три.js выгружается из памяти (`dispose`). До готовности или если WebGL недоступен: **запасные постеры**, подготовленные заранее из существующих рендеров `hardware/enclosure/render/` (`01_assembly_front` для 1 и 6, `07_left_speaker` для 3, `04_underside` для 4, `03_lid_open` для 5; для сцены 2 нужен рендер сверху, которого нет в папке: дозаказать у владельца модели).
- Подписи-выноски: статичные, на изображении, без линий-лидеров, либо списком под изображением.
- Отключается всё остальное: проявление при загрузке (п. 3.3), счёт чисел, параллакс, пульсации, плавная прокрутка якорей; переходы остаются только как `opacity` 150 мс, если нужны для фокуса.
- Шапка и стекло остаются.
- Режим включается: системной настройкой, ручным переключателем «Анимации» в подвале и шапке-меню (значения «Как в системе / Включены / Выключены»), сторожем (п. 4.5), `saveData`, высотой окна < 560 px (ландшафт телефона), отсутствием WebGL2/WebGL.
- Без JavaScript: весь текст и таблица читаются, сцены идут блоками с запасными постерами; кнопки «Войти» и «Создать ферму» это ссылки на `/login` и `/register`.

### 5.2 Движение вообще (когда reduce не включён)

Осмысленное и сдержанное: прокрутка управляет моделью, текст появляется один раз по `P`, кнопки: hover `translateY(-1px)` 120 мс, нажатие `scale(.98)`. Нет автопроигрывания, нет каруселей, нет бесконечных анимаций. Единственное повторяющееся движение это подсказка «Листайте» (стрелка покачивается 3 раза и останавливается).

### 5.3 Доступность (WCAG 2.2 AA)

- Первая ссылка страницы: «Перейти к содержимому» (`#main`), видна при фокусе. Структура: `header`, `nav` (`aria-label="Основная"`), `main`, `footer`; один `h1`; сцены `h2`, подразделы `h3`; порядок в DOM = порядок чтения.
- Канва: `<canvas aria-hidden="true">`; рядом в блоке `figure` с `role="img"` и `aria-label`: «Трёхмерная модель ошейника Qamqor. Показан вид: {название сцены}», `aria-label` обновляется при смене сцены (не `aria-live`, чтобы не говорить при прокрутке).
- Текст всех сцен всегда в DOM и доступен скринридеру; визуально скрытый (`opacity: 0`) текст остаётся читаемым через доступное дерево (не `display: none`). Для сцен вне зоны текст в доступном дереве всё равно присутствует, поэтому нет скрытия по `aria-hidden`.
- Фокус: двойное кольцо (токены п. 1.1) на каждом интерактивном элементе, не скрыт шапкой (`scroll-padding-top` = высота шапки + 16).
- Мобильное меню: кнопка с `aria-expanded`, диалог `role="dialog" aria-modal="true"`, Esc закрывает, фокус заперт, возвращается на кнопку.
- Переключатель языка: настоящие ссылки/кнопки `lang="kk"`, `lang="ru"`, `lang="en"` на каждом пункте, `aria-current`. Атрибут `<html lang>` обновляется.
- Цели касания не меньше 44 × 44 (AA 24, цель выше). Расстояние между целями ≥ 8.
- Уменьшение прозрачности, высокий контраст (`forced-colors`) — п. 1.3.
- Масштаб текста 200 % и zoom 400 % (reflow при 320 px): без потери содержимого, без горизонтальной прокрутки; пиннинг отключается, если высота окна < 560 или масштаб увеличил CSS-высоту ниже порога.
- Видео и звука нет.
- Тексты ссылок осмысленные («Создать ферму», не «Нажмите здесь»).

### 5.4 Состояния лендинга

| Состояние | Поведение |
|---|---|
| Загрузка (до three) | постер hero + текст сцены 1 + все остальные блоки на месте; никаких пустых белых областей |

### 7.3 Вход и регистрация (`/login`, `/register`)

Раскладка (десктоп ≥ 900): две колонки 50/50: слева ночь `night-0` с видом модели (статичный постер, не живая канва) и коротким текстом «Qamqor. Прототип.»; справа форма на `surface-0`, ширина 400. - Животные: точки по A3 п. 7.6 (норма: белая с тёмным кольцом; вне зоны: `signal-map` с белым кольцом и окантовкой, пульс трижды; нет связи: полая; без границы: метка «забор с чертой»). Кластер при > 30 маркерах: скруглённый квадрат 36 × 28 `primary`, белое число.
- Выбранное: белое кольцо 2,5 и подпись-стекло («Корова #0142», статус). В списке выбранная строка получает фон `surface-1` и `check-circle`.

Подложка (вопрос D3): пока решение не принято, карта стоит на нейтральной подложке `surface-1` с лёгкой сеткой `line-soft` и подписью «Подложка карты подключается», загоны и животные отрисованы поверх; это рабочий режим, а не заглушка-обман: данные реальные. После решения архитектора подставляется источник тайлов и его лицензионная строка.

Состояния:

| Состояние | Вид |
|---|---|
| Загрузка | карта `surface-1` + скелетон панели, подпись «Загружаем карту» |
| Пусто (нет животных) | на карте пусто; панель: «В стаде пока никого» + кнопка «Добавить животное» (W) |
| Нет загонов | подсказка в панели `body`: «Границы рисуются в приложении» (D4) + ссылка на страницу приложения? ссылки нет, не выдумываем: просто текст |

### 7.6 Стадо (`/app/herd`, `/app/herd/:id`)

- ≥ 900: таблица с колонками «Номер», «Кличка», «Вид», «Загон», «Ошейник», «Статус», «Был(а) на связи». Строка 64 высотой, цель клика вся строка (`<a>`), сортировка по статусу и времени. Заголовки таблицы `<th scope="col">`.
- < 900: карточки-строки A3 п. 7.5 (маркер статуса, название, подпись, статус справа).

Состояния: загрузка (скелетон строк), пусто («В стаде пока никого» + «Добавить животное»), пусто после фильтра («Ничего не найдено» + «Сбросить фильтры»), ошибка, нет связи.

### 7.7 Оповещения (`/app/alerts`)

Список карточек A3 п. 7.7 (радиус 22, полоса 4 px, заголовок, детали, время). Фильтры-чипы: «Активные», «Принятые», «Закрытые»; по типу (выпадающий). Действия: «Принять» (`PATCH status = ACKNOWLEDGED`), «Закрыть» (`RESOLVED`), «Показать на карте» (если есть `lat/lng`), вверху «Отметить все прочитанными» (`POST /alerts/read-all`). ### 7.8 Ошейники (`/app/collars`)

Список (таблица ≥ 900, карточки ниже): «Идентификатор» (deviceId), «Животное» (или «Не привязан»), «Статус» (7.4: «На связи» / «Нет связи · {время}» / «Не привязан» / «Ещё не выходил на связь»), «Сигнал» (RSSI, если есть, иначе «—»), «Прошивка» (если есть, иначе блок скрыт), «Был(а) на связи». Время «был на связи» относительное, абсолютное в подсказке. Заряда нет. Порог «нет связи» не придумывается: по контракту ошейник считается офлайн, если нет пинга дольше 15 минут (3 × 300 с); пишем в справке карточки «Считается без связи, если не выходил на связь дольше 15 минут» (значение из контракта).

Вверху справа кнопка **«Подключить устройство»** (основная; только владелец; у работника кнопка скрыта, вместо неё в пустом состоянии: «Подключать ошейники может владелец фермы»).

Действия в карточке (`/app/collars/:deviceId`): «Привязать к животному» / «Отвязать» (W, `PATCH`), «Отправить тестовый звук», «Отправить тестовую вибрацию» (W; после нажатия: «Команда поставлена в очередь. Ошейник получит её при следующем выходе на связь» — не обещаем мгновенность), «Обновить ключ» (O), «Удалить» (O). Тестового импульса нет.

Состояния списка: пусто («Ошейников пока нет» + «Подключить устройство» для O), загрузка, ошибка, нет связи (кнопки записи выключены).

### 7.9 Поток «Подключить устройство» (`/app/collars/connect`)

Цель: человек, у которого в руках ESP32, понимает, что куда вставить, и не теряет секрет. Трёхшаговый поток, индикатор шага A3 п. 7.3б («Шаг n из 3»); страница, не модальное окно (секрет на странице безопаснее, чем в диалоге, который случайно закрывают). Максимальная ширина 640.

**Шаг 1 из 3. «Назовите устройство»**

- Пояснение `body`: «Каждый ошейник на плате ESP32 узнаёт сервер по идентификатору и секретному ключу. Идентификатор вы придумываете сами, ключ создаёт сервер.»
- Поле «Идентификатор устройства» (`deviceId`), подсказка: «Латинские буквы, цифры, дефис и подчёркивание, от 3 до 40 знаков. Например, COLLAR-01». Валидация на лету по `^[A-Za-z0-9_-]{3,40}$`.
- Поле «Животное» (необязательно, выпадающий список животных без ошейника): «Можно привязать позже».
- Кнопка «Создать ключ» (основная). Ошибки: `CONFLICT` «Такой идентификатор уже занят», `VALIDATION` «Проверьте идентификатор», `FORBIDDEN_ROLE` «Подключать устройства может только владелец».

**Шаг 2 из 3. «Сохраните ключ»** (экран после `POST /devices`; ответ содержит `deviceSecret`)

Раскладка карточки (`surface-2`, радиус 24), сверху вниз:

1. Предупреждение сверху (иконка `warning`, цвет `warning` `#7A4A00`, фон `surface-1`, 7.09 контраст на `surface-0`; текст `ink`): **«Ключ показывается один раз. После выхода с этой страницы его нельзя посмотреть. Если потеряете, создайте новый ключ (старый перестанет работать).»**
2. Блок «Идентификатор»: значение + кнопка «Скопировать».
3. Блок «Секретный ключ»: значение крупно (`title-2`), **моноширинное системное начертание** (`ui-monospace`) для различимости символов (исключение из правила A3, потому что ключ переписывают; `letter-spacing` .04em; группами по 4 знака, группы разделены тонким пробелом, без разрыва строки внутри группы; при выделении копируется без пробелов). По умолчанию **показан** (одноразовый экран), кнопка «Скрыть / Показать» (`aria-pressed`) для ситуаций с чужим взглядом. Кнопка «Скопировать ключ» (основная, 56): после нажатия подпись «Скопировано» 3 секунды + `aria-live="polite"` озвучивает «Ключ скопирован». Запасной вариант без Clipboard API: поле выделяется целиком (`select()`) и подсказка «Нажмите Ctrl+C».
4. Блок «Что вставить в прошивку» (раскрытый): список из 3 строк «настройка → значение»:
   - «Идентификатор» → значение deviceId;
   - «Секретный ключ» → значение;
   - «Адрес сервера для данных» → `{origin}/api/v1/device/telemetry`, метод `POST`, заголовок `Authorization: Bearer {ключ}`.
   Кнопка «Скопировать все настройки» (текст из трёх строк). Подпись `caption`: «Названия параметров в прошивке уточняются при её готовности» (папка `esp/` пока содержит только README; формат строк не придумываем).
5. Флажок «Я сохранил ключ в безопасном месте» (по умолчанию снят). Кнопка «Продолжить» (основная) **выключена, пока флажок не отмечен**. Выход иным путём (ссылка «Назад», закрытие вкладки, смена маршрута): перехватывается `beforeunload` и диалогом «Вы не сохранили ключ. Показать его снова нельзя. Выйти? [Остаться] [Выйти и создать новый ключ позже]».

Безопасность и ограничения интерфейса: секрет хранится только в памяти компонента (не в `localStorage`, не в URL, не в логах и аналитике), очищается при уходе со страницы, не попадает в историю состояния; `autocomplete="off"`; страница отправляет `Cache-Control: no-store`; скриншот делает пользователь сам.

Состояния шага 2: загрузка (кнопка «Создаём ключ…»), ошибка создания (остаёмся на шаге 1, сообщение), потеря сети после создания (ключ уже на экране; мы не повторяем запрос автоматически: двойной запрос выдал бы второй ключ; показывается плашка «Нет сети. Скопируйте ключ сейчас»).

**Шаг 3 из 3. «Проверьте связь»**

- Поясняющий текст: «Прошейте ESP32 этими настройками и включите ошейник. Первый сигнал придёт при ближайшем выходе на связь, обычно в течение 5 минут» — **число 5 минут это из контракта (`NORMAL_PING_INTERVAL_SEC = 300`), указывать как «до 5 минут» допустимо; если интервал изменится, строка меняется**.
- Живой статус: опрос `GET /devices/:deviceId` каждые 10 секунд, `aria-live="polite"`: «Ожидаем первый сигнал…» (спиннер, у `prefers-reduced-motion` статичная точка) → «Ошейник на связи» (галочка, `ok`) + кнопки «Перейти к ошейнику», «Подключить ещё один».
- Через 15 минут без сигнала: «Сигнала пока нет. Проверьте, что ошейник включён и в зоне сети, настройки в прошивке совпадают» + кнопки «Проверить снова», «Закончить» (ошейник остаётся в списке со статусом «Ещё не выходил на связь»).
- Нет сети: опрос приостановлен, плашка баннера.

**Ротация ключа** (`POST /devices/:id/rotate-secret`, только владелец): кнопка «Обновить ключ» в карточке; диалог `role="dialog"`: «Старый ключ перестанет работать. Ошейник пропадёт со связи, пока вы не пропишете новый ключ в прошивке. Продолжить?» + поле «Для подтверждения введите идентификатор {deviceId}» + кнопки «Отмена» (по умолчанию в фокусе) и «Обновить ключ» (разрушительная, `signal`, белый 6.31). Успех переводит на тот же экран «Сохраните ключ» (шаг 2 без шага 1) с тем же предупреждением и флажком. Работник кнопки не видит.

**Удаление** (`DELETE`, владелец): диалог «Удалить ошейник {deviceId}? Он больше не сможет присылать данные. Животное останется в стаде без ошейника.», подтверждение вводом идентификатора.

### 7.10 Настройки (`/app/settings`)

Разделы вкладками (≥ 900 слева список, ниже верхние вкладки-чипы): «Ферма» (O): название, описание, часовой пояс, переключатель «Работник может менять границы» (по умолчанию выключен; подпись: «Работник сможет рисовать и менять границы загонов в приложении»), «Люди» (O): список участников и приглашений (`GET /farms/:id/members`), «Пригласить по email» (`POST …/invitations`; если `delivered: false`, показываем `inviteUrl` с кнопкой «Скопировать ссылку» и пояснением «Письмо не отправлено: на сервере не настроена почта. ## 9. Критерии приёмки (для QA)

Лендинг:

1. Все сцены п. 3.2 отрисованы на 1440 × 900, 1280 × 720, 768 × 1024, 375 × 812, 320 × 640: модель целиком в кадре, текст не перекрывает её, выноски на месте; прокрутка назад отматывает.
2. Ничего не пропущено из п. 3.4; нет ни одной выдуманной цифры; нет слов «импульс», «электрошок», «пульс», «заряд»; на сайте нет ни одной ИИ-иллюстрации (или она подписана).
3. Размеры 210 × 80 × 90 мм и надпись «прототип, размеры уточняются» присутствуют в сцене 6 и в таблице; примечание про 89 мм есть.
4. Бюджет п. 4.1 подтверждён числами из отчёта сборки и Network; Lighthouse mobile: LCP ≤ 2,5 с, CLS ≤ 0,05.
5. `prefers-reduced-motion: reduce`: нет пиннинга, нет анимации по прокрутке, статичные позы показывают то же содержимое (проверка в эмуляции DevTools и в системе).
6. Режимы: без WebGL, без JS, `saveData`, `forced-colors`, `prefers-reduced-transparency`, потеря контекста WebGL: страница читаема, кнопки работают.
7. Доступность: контраст п. 1.2 подтверждён измерением на отрисованных страницах (особенно текст на стекле); клавиатура проходит всю страницу; фокус виден на ночи и на свету; диалог меню: Esc, ловушка, возврат фокуса; skip-link; ru и kk, 200 % и 400 % масштаб.
8. Нет горизонтальной прокрутки на 320, 375, 768, 1280, 1440 (`scrollWidth ≤ innerWidth`), в ru, kk, en; длинные слова не рвутся по буквам.
9. Верхний регистр и казахские буквы Ә Ғ Қ Ң Ө Ұ Ү Һ І отрисованы Inter на весах 400, 600, 700 (визуально).

Кабинет:
